# Filesystem Layout

## Project root

```

├── README.md

├── pyproject.toml           # CLI package + dependency groups
├── mkdocs.yml               # Docs site configuration

├── .gitignore
├── docker/

│   ├── entrypoint.sh        # Runs INSIDE Android via stealth.rc
│   └── stealth.rc           # Android init trigger
├── presets/
│   ├── default.yaml         # Cheap baseline preset
│   └── stealth.yaml         # Adds Shamiko for anti-detection research
├── scripts/

├── src/beetroot/            # CLI Python package
│   ├── cli.py

```

## Per-instance directory

```
instances/<name>/
├── beetroot.yaml     # Source of truth — NOT gitignored
├── .env              # Generated from beetroot.yaml — gitignored
├── data/             # Bind-mount → /data inside Android — gitignored
├── modules/          # Bind-mount → /flash_dir (read-only) — gitignored
└── frida-server      # Bind-mount → /data/local/tmp/frida-server — gitignored
```

### `beetroot.yaml`

The configuration file for this instance. **Not gitignored.** If you commit it, you get a reproducible device config that collaborators can replicate by running `beetroot create <name>` with your YAML.

### `.env`

Generated by the CLI via `config.render_env()`. Never hand-edited — edit `beetroot.yaml` instead and run `beetroot apply`. Contains all the `${VAR}` substitutions that `compose.yaml` needs: `ADB_PORT`, `FRIDA_PORT`, `MEM_LIMIT`, etc.

### `data/`

The Android `/data` partition, bind-mounted read-write into the container. This is where Android stores app installs, settings, accounts, and all user state. It's the most important artifact of an instance — everything else can be regenerated, but `data/` cannot.

Gitignored. Can be gigabytes in size. Snapshot with `cp -a` or `tar --zstd` before destructive research.

### `modules/`

The Magisk module staging area, bind-mounted read-only into the container at `/flash_dir`. The CLI mirrors `beetroot.yaml`'s `modules:` list here on `create` and `apply`. Gitignored (the zips can be large and are re-downloadable).

### `frida-server`

The Frida server binary for this instance, bind-mounted into the container at `/data/local/tmp/frida-server`. Downloaded from GitHub releases by `frida_dl.py` and cached in `.cache/frida/<version>/` to avoid re-downloading across instances. Gitignored.

## What to commit

The rule is simple: commit `beetroot.yaml`, ignore everything else under `instances/`.

If you want a reproducible research environment, commit `instances/<name>/beetroot.yaml`. A collaborator with the repo can run:

```bash
beetroot create <name>
beetroot up <name>
```

...and get the same Android version, Frida version, modules, and Magisk config — just with a freshly initialized `/data`.

## Cache directory

```
.cache/
└── frida/
    └── <version>/
        └── frida-server   # Decompressed binary, reused across instances
```

The Frida binary cache avoids re-downloading the same version for multiple instances. Gitignored. Safe to delete — the CLI re-downloads on next `apply` or `create`.
